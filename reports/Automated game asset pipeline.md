# Script the sources, generate the gaps, stylize everything

The pipeline that fits this project is mostly deterministic Python code, with AI playing a small part. Keyless CC0 APIs supply surface textures: Poly Haven and ambientCG already have mudbrick, clay plaster, cracked mud, reed roofs and sandstone. Kenney, KayKit and Quaternius supply generic low-poly props, palms and animated animals. Everything specifically Mesopotamian has to be generated in-house with headless Blender and numpy scripts: ziggurat, mudbrick house kit, mudhif reed hall, reed boats, canals and levees. The reason is simple. No permissive source has low-poly versions of these, and the museums that hold the famous Ur objects (British Museum, Penn) license them non-commercially. Every source, whether a CC0 photoscan, a Quaternius glTF or an AI texture, then goes through one stylization stage that locks it to a fixed project palette and flat-shades it. That stage is what makes mixed sources read as one Valheim-like world. It is the automated version of the "few simple rules" approach that Sea of Thieves and Valheim use. On the RX 5700 XT, local AI is worth using for 2D only: tileable textures, decals and concept art through stable-diffusion.cpp on Vulkan or CPU. None of the strong 2025–2026 image-to-3D models run on gfx1010. Two legal points need attention before any asset lands in the repo. Quaternius switched to a no-redistribution licence on 2026-08-28. Steam now requires disclosure of shipped AI content. Both fit the current set-up (a private repo shared with Tommy, a Steam release, a developer in Turkey), provided a manifest records the source, licence and acquisition date of every file.

## CC0 APIs cover surfaces well; low-poly kits cover only the generic world

**Poly Haven has the cleanest automation story.** It needs no key and no auth. `GET /assets?type=textures&categories=…` lists assets and `GET /files/{id}` returns direct CDN URLs with an md5 per file. Everything is CC0 ([Poly Haven API README](https://github.com/Poly-Haven/Public-API/blob/master/README.md)). A probe on 2026-09-26 found a Near-East-relevant set: `clay_block_wall`, `clay_plaster`, `patterned_clay_wall`, `mud_cracked_dry_03`, `dry_mud_field_001`, `reed_roof_03/04`, `thatch_roof_angled`, `palm_bark` and several sandstone brick walls. The file tree includes a DirectX-convention `nor_dx` normal and a packed `arm` (AO/rough/metal) map, and both map directly onto UE conventions. The only obligation is that **every API call must carry a unique User-Agent or Referer naming your software** ([Poly Haven API ToS](https://github.com/Poly-Haven/Public-API/blob/master/ToS.md)). The ToS credit clause covers surfacing the live API inside a product, and an offline build-time downloader does not do that. Its 521 models are mostly South African succulents, and none is a date palm, so use Poly Haven for textures and HDRIs only.

**ambientCG** adds about 2,011 CC0 materials through a keyless v3 API (`/api/v3/assets?q=mud&type=material&include=downloads,maps`). Downloads are per-resolution ZIPs, and the 1K-JPG of one ground material is 9 MB against 1.14 GB for the 8K-PNG ([ambientCG API v3](https://docs.ambientcg.com/api/v3/assets/); [licence](https://docs.ambientcg.com/license/)). It has **0 reed and 0 thatch materials**, so those come from Poly Haven. It is also run by one person who warns the API is "not as reliable or stable as needed for an 'enterprise-level' application" ([ambientCG About the API](https://docs.ambientcg.com/api/)). Download sequentially and cache by checksum.

For models, stylistic fit and scriptability pull in different directions:

| Source | Licence | How to automate | Best use here |
|---|---|---|---|
| Kenney | CC0 ([Nature Kit](https://kenney.nl/assets/nature-kit)) | Scrape the hashed ZIP URL from each pack page; GLB, FBX, OBJ | 6 palm variants, cactus, rocks, wheat, pots, fences |
| KayKit | CC0 ([Medieval Hexagon](https://kaylousberg.itch.io/kaykit-medieval-hexagon)) | `git clone` from the `KayKit-Game-Assets` GitHub org; the itch-only packs need a manual download | Rigged humanoids with 75 animations ([Adventurers](https://github.com/KayKit-Game-Assets/KayKit-Character-Pack-Adventures-1.0)), crates, barrels |
| Quaternius | **QAL v1.0 since 2026-08-28** ([licence](https://quaternius.com/license.html)) | `gdown --folder` on Google Drive links; itch for MegaKits | Closest Valheim look; animated donkey, bull, horses, deer, dogs ([animal pack](https://quaternius.com/packs/ultimateanimatedanimals.html)) |
| Poly Pizza | Mixed CC0 / CC-BY | API needs a free key in `X-Auth-Token` (401 without one) | Date palm, amphora, chariot, camel, lion, reed-ish boats |
| Sketchfab | Filter to `cc0` or `by` | Search is keyless; `/download` needs an OAuth token and links expire after about 300 s ([docs](https://sketchfab.com/developers/download-api/downloading-models)) | Museum scans and low-poly CC-BY ziggurats |
| Fab / Megascans | Fab Standard | No API (Cloudflare 403); manual only | Optional; photoreal, poor fit |

**The Quaternius change is the item most likely to cause trouble later.** QAL v1.0 still allows free commercial use with no credit, and it explicitly lets you "authorize contractors and collaborators" to work with the assets. It forbids redistributing them "as a standalone asset … regardless of how much the Assets have been modified." It also fixes the governing version at the date you obtained the files ([Quaternius License](https://quaternius.com/license.html)). Meanwhile the individual pack pages still say "CC0", so the site contradicts itself ([Stylized Nature MegaKit](https://quaternius.com/packs/stylizednaturemegakit.html)). Treat anything downloaded after 2026-08-28 as QAL. Record the download date for each pack. Keep the raw files only in the private repo shared with Tommy, which fits the collaborator grant, and never in a public repo or mod kit. Fab Standard assets follow the same rule: they may be shared "via a private repository with your collaborators" ([Fab EULA](https://www.fab.com/eula)).

**On Poly Pizza, filter strictly by the licence field.** Most "Poly by Google" items, including the one date palm, are CC-BY and need credit ([Poly Pizza search](https://poly.pizza/search/palm%20tree)). The API field names and rate limits come from a third-party skill document, because the official docs page renders only in JavaScript ([secondary doc](https://github.com/jasonkneen/tiny-world-builder/blob/main/.agents/skills/poly-pizza-api/SKILL.md)). Confirm them with the first call. On Sketchfab, CC-BY results include obvious third-party IP such as "Donkey (Pocket Shrek)". Only institutional CC0 uploads (clevelandart, artsmia, mkghamburg) are trustworthy without manual review.

**The gap list is concrete.** No permissive source has a CC0 ziggurat, a reed boat, a mudhif, an oxcart, an onager or a Mesopotamian lion with animations. A donkey is the closest onager proxy. Those gaps define the procedural backlog.

## Heritage sources are references, not drop-in props

Most of what exists about Ur itself is off-limits. **British Museum and Penn's Ur Online are CC BY-NC-SA**, so they are excluded ([BM terms](https://www.britishmuseum.org/terms-use/copyright-and-permissions/images-and-photography); [Ur Online](http://www.ur-online.org/about/8/)). Penn's OPenn images are CC BY-SA 2.0, which is fine for reference but should not ship ([OPenn](https://openn.library.upenn.edu/html/0016.html)). The Louvre requires paid permission ([Louvre CGU](https://collections.louvre.fr/en/page/cgu)), and ISAC Chicago images are for research only ([ISAC](https://isac.uchicago.edu/research/photo-requests-and-permissions)). A live search on 2026-09-26 found **no CC0 or CC-BY scan of the Standard of Ur, the Royal Game of Ur or the Ur lyres** anywhere. Those icons have to be modelled.

Three sources are usable, and all are keyless for discovery:

- **The Met's collection API.** Search department 3, "Ancient West Asian Art". It returned 772 cylinder seals, 301 "Sumerian" objects and 183 bricks with images. Each object carries an `isPublicDomain` flag and full-resolution `primaryImage`/`additionalImages` URLs ([Met API](https://collectionapi.metmuseum.org/public/collection/v1/search?departmentId=3&hasImages=true&q=cylinder%20seal); [object 323735](https://collectionapi.metmuseum.org/public/collection/v1/objects/323735)). This is the best source for pattern, decal and palette reference.
- **The Cleveland Museum of Art API.** It filters with `cc0=1`, and records include a `sketchfab_id` that links directly to the CC0 3D scan. The Statue of Gudea is one example ([CMA 1963.154](https://openaccess-api.clevelandart.org/api/artworks/1963.154)).
- **Wikimedia Commons.** You can put a licence filter inside the search (`haswbstatement:P275=Q6938433` for CC0) and read `extmetadata` for Artist and LicenseShortName. This returned CC0 ziggurat photos and public-domain mudhif photos, including one by Gertrude Bell from around 1918 ([Commons API](https://commons.wikimedia.org/w/api.php)). Expect heavy CC BY-SA and discard it.

**The Smithsonian's 3D API works without a key but has nothing Mesopotamian.** Searches for Mesopotamia, cuneiform, Sumer, Babylon and Uruk all returned 0 rows ([3d-api.si.edu](https://3d-api.si.edu/api/v1.0/content/file/search?q=Iraq&rows=5)). It is still useful as a template: it ships each model as a 20k "thumb" and a 150k "high" Draco GLB, which is a sensible LOD naming convention for this pipeline.

The CC0 scans that do exist need heavy processing and period tagging. **Face counts run from 65k (the artsmia seals, CMA Gudea) through 2–4M (the mkghamburg tablets) to 10M (the hmane tablet)** ([Sketchfab search](https://api.sketchfab.com/v3/search?type=models&q=cuneiform&downloadable=true&license=by)). Most of them are also **Neo-Sumerian, Old Babylonian or first-millennium Assyrian**, not third-millennium Ur. Tag each asset with its period, or a Gudea statue or a 9th-century BCE relief will quietly end up in the wrong era. In practice these scans work best as sculpting references, as small hero props after decimation, or as sources for relief patterns on decals.

**For sound, script Freesound and add Sonniss by hand.** The Freesound API filters with `license:"Creative Commons 0"` or `"Attribution"`. Search and HQ OGG previews work with a simple token. Original-quality downloads need OAuth2 and are capped at **30 per minute and 500 per day** ([Freesound resources](https://freesound.org/docs/api/resources_apiv2.html); [throttling](https://freesound.org/docs/api/overview.html)). Nobody has confirmed that shipping preview transcodes in a commercial game is within Freesound's terms, so do the one-time OAuth login and fetch originals. The yearly **Sonniss #GameAudioGDC bundle** is royalty-free for commercial use and needs no attribution, but it has no API and forbids AI training ([Sonniss licence](https://sonniss.com/gdc-bundle-license/)). Download it once, index it locally by filename keyword, and use it for ambience and Foley. **BBC RemArc is non-commercial, so it is excluded** ([summary](https://www.avosound.com/en-us/licensing/remarc-license)).

## Procedural generation fills the gaps: buildings, palms, floodplain

**Blender is not installed on the machine yet**, and every procedural and stylization step depends on it. Installing the current LTS is step zero; the live manual is titled Blender 5.2 LTS ([Blender manual](https://docs.blender.org/manual/en/latest/modeling/modifiers/geometry_nodes.html)). Run it in background mode with one process per asset (`blender -b --factory-startup -P gen.py -- --seed N --out x.glb`). One process per asset is not optional. Cycles bakes do not free memory between runs, and the known workaround is a driver that restarts Blender for each object ([cycles-bake-workaround](https://github.com/Mateusz-Grzelinski/cycles-bake-workaround)). Geometry Nodes trees can be built and attached from Python ([CGWire](https://blog.cg-wire.com/blender-scripting-geometry-nodes-2/)). Force a depsgraph update after changing modifier inputs ([T87006](https://developer.blender.org/T87006)), and avoid the experimental Python GN node, which can crash Blender ([repo](https://github.com/Snowdaw/blender-python-geometry-node)).

The research turned up **no maintained headless building-grammar library**, and this style does not need one. Mesopotamian mudbrick architecture is rectilinear boxes, flat roofs, parapets, few openings and courtyards. A few hundred lines of bmesh code can produce it: footprint, extrude, inset parapet, boolean doorways, then a seeded vertex jitter for the hand-made wobble. A better plan than generating whole houses is to generate a **10–20 piece modular kit on a fixed grid** (walls, corners, parapets, doorways, stairs, ziggurat terraces) and assemble it in UE. The assembled buildings then stay instanced. The mudhif is a parabolic reed-bundle arch swept and repeated along the hall with a mat skin over it. A date palm is a curved 8–10-sided trunk with 20–30 frond cards on a 137.5° golden-angle spiral. Both are small seeded bmesh scripts. **friggog/tree-gen covers broadleaf trees such as tamarisk.** Its code is GPL, but the author states generated models are free for any use "apart from direct sale as assets" ([tree-gen](https://github.com/friggog/tree-gen)). Driving it headless is untested.

**Terrain should be plain numpy, not Gaea.** Gaea's CLI build is a Windows `.exe`, and command-line use reportedly needs a paid Professional licence ([Gaea Build Swarm](https://docs.quadspinner.com/Guide/Build/Swarm.html)). The Mesopotamian floodplain is almost flat, so the interesting features are generated by rule: gentle FBM and a slope toward the river, a channel carved with a distance field around a spline, Gaussian levees along the banks, trapezoid canals with spoil banks, and ridge-noise dunes at the desert edge. `dandrino/terrain-erosion-3-ways` supplies tested Linux numpy FBM, river-network and erosion code if you want more ([repo](https://github.com/dandrino/terrain-erosion-3-ways)). The same distance fields produce splat masks for wet silt, irrigated fields, sand and rock. The output is a 16-bit heightmap plus 8-bit layer PNGs. UE exposes `LandscapeProxy.landscape_import_heightmap_from_render_target()` to Python ([LandscapeProxy](https://docs.unrealengine.com/5.4/en-US/PythonAPI/class/LandscapeProxy.html)). Creating a new Landscape actor from a file in 5.8 Python has no verified recipe. Plan on a one-time manual import and scripted updates after that.

**Textures, decals and VFX need no GPU.** Material Maker 1.5 (MIT, January 2026) brought back a batch CLI: `material_maker --export-material --target Unreal -o out/ *.ptex` ([docs](https://rodzill4.github.io/material-maker/doc/command_line.html); [1.5 notes](https://digitalproduction.com/2026/01/26/material-maker-1-5-adds-dds-fbx-cli-10-new-nodes/)). It needs a real rendering context, so do not pass `--headless`, and the Linux path is "untested" ([practitioner notes](https://github.com/graysonchalmers/Tool-MaterialMaker-MCP)). Running it under `xvfb-run` with Mesa llvmpipe is plausible but unproven. The dependable fallbacks are Blender's Brick and Voronoi nodes baked on CPU Cycles, and PIL/numpy compositing for trim sheets (mudbrick course, plaster, reed mat, beam, rope bands) and decal atlases. Stylized smoke, dust and fire flipbooks are an FBM-times-radial-falloff loop quantized to 3–4 tones and tiled into an 8×8 SubUV atlas. That takes a few seconds of CPU and avoids Mantaflow entirely. For Niagara, script only duplication of hand-built template systems and swaps of their parameters or flipbooks. Building systems from Python is impractical.

## Local AI earns a place for 2D only on the RX 5700 XT

**gfx1010 is still not in AMD's official ROCm list.** AMD's TheRock build system now publishes gfx1010 PyTorch wheels, and SD 1.5 runs at about **1.5 it/s at 512×512** on an RDNA1 part. The same tracking issue shows the limits: int8 fails, and Flux gives garbled images on the Triton backend ([TheRock #7609](https://github.com/ROCm/TheRock/issues/7609)). gfx101X builds also lack hipBLASLt and fused attention ([unsloth PR](https://github.com/unslothai/unsloth/pull/9138)). The lower-risk path is **stable-diffusion.cpp** (MIT). It has Vulkan and CPU backends and `--circular` flags for seamless tiling, and supports SD1.5/SDXL, LoRA, VAE tiling and ESRGAN ([sd.cpp](https://github.com/leejet/stable-diffusion.cpp)). It uses the same RADV stack as the llama.cpp setup that already works on this card. Given the card's history of command-processor hangs, run short headless batches with the display on the Intel iGPU. Avoid the old `HSA_OVERRIDE_GFX_VERSION=10.3.0` trick, which makes rocBLAS load RDNA2 code. Nobody has benchmarked sd.cpp speed on this card, so measure it first.

Two small tools complete the texture side. **StableMaterials** (openrail, 0.9B parameters) generates tileable basecolor, normal, height, roughness and metallic maps at 512 px in 4 LCM steps ([HF](https://huggingface.co/gvecchio/StableMaterials); [paper](https://arxiv.org/html/2406.09293v3)). **DeepBump** runs on ONNX on the CPU and turns an albedo into normal and height maps ([DeepBump](https://github.com/HugoTini/DeepBump)). For a flat-shaded look, SD textures quantized to the palette plus DeepBump normals cover most material needs.

**Image-to-3D is out of reach locally.** TRELLIS.2 requires "an NVIDIA GPU with at least 24GB" ([TRELLIS.2](https://github.com/microsoft/TRELLIS.2)). Hunyuan3D-2 needs 16 GB and CUDA-compiled rasterizers for its texture stage ([Hunyuan3D-2](https://github.com/Tencent-Hunyuan/Hunyuan3D-2)). What runs on CPU is TripoSR (MIT, vertex-coloured output; [repo](https://github.com/VAST-AI-Research/TripoSR)) and Stable Fast 3D (`SF3D_USE_CPU=1`, with a built-in remesh to a target vertex count; [repo](https://github.com/Stability-AI/stable-fast-3d)). Both produce dense triangle soup that needs voxel remesh, decimation and repainting. For low-poly props, kitbashing CC0 kits or a bmesh script is usually faster. If you want high-quality AI meshes, rent a 24 GB NVIDIA GPU for TRELLIS.2, which is MIT-licensed. Hunyuan3D's licence excludes only the EU, UK and South Korea, so Turkey is inside its territory. Its restriction on where the model is used could be read conservatively for a game sold into the EU, so get legal advice if the game grows ([Hunyuan3D-2.1 licence](https://github.com/Tencent-Hunyuan/Hunyuan3D-2.1/blob/main/LICENSE)).

**For sound, Stable Audio Open 1.0 is the only commercially clean local SFX model.** It produces up to 47 s of 44.1 kHz stereo and was trained on CC-licensed Freesound and FMA audio ([model card](https://huggingface.co/stabilityai/stable-audio-open-1.0)). It falls under the Stability Community License, which is free up to **US$1M annual revenue** ([Stability licence](https://stability.ai/license)). SF3D is under the same licence. AudioLDM 2 (CC-BY-NC-SA) and AudioGen (CC-BY-NC) outputs must not ship ([AudioLDM2](https://huggingface.co/cvssp/audioldm2); [audiocraft #198](https://github.com/facebookresearch/audiocraft/issues/198)). UniRig is an MIT auto-rigger ([UniRig](https://github.com/VAST-AI-Research/UniRig)), but its runtime needs are unverified. Quaternius and KayKit already ship rigged, animated animals and humanoids, so skip AI rigging.

**Every AI-made asset that ships must be disclosed.** Steam's January 2026 disclosure form covers "pre-generated" content that "ships with your game, and is consumed by players". It exempts behind-the-scenes efficiency tools ([PC Gamer](https://www.pcgamer.com/software/ai/steam-updates-ai-disclosure-form-to-specify-that-its-focused-on-ai-generated-content-that-is-consumed-by-players-not-efficiency-tools-used-behind-the-scenes/)). Concept art that is then modelled by hand arguably falls outside the form. SD textures in the build do not.

## One stylization pass and a scripted UE import unify every source

The stylization stage matters more than any single source. **Pillow's `Image.quantize(palette=…, dither=Dither.NONE)` locks any texture to a fixed project palette** after a `Resampling.BOX` downscale ([Pillow docs](https://pillow.readthedocs.io/en/stable/reference/Image.html)). Only a fixed palette gives consistency across sources. Per-image k-means palettes break it. Fortnite's artists found that simplified photo textures stayed "too noisy" and went back to hand-painting ([Habrador](https://blog.habrador.com/2018/08/stylized-graphics-fortnite-sea-of-thieves.html)). So median-filter or heavily downscale photoscans before quantizing, and drop their normal and roughness maps. On the mesh side, **gltfpack `-si R` is the CLI simplifier** ([meshoptimizer](https://meshoptimizer.org/gltf/)). A headless Blender script handles the stylistic part: weld, voxel remesh for AI or scan meshes, collapse and planar decimate, flat shading, and a bake of albedo and AO into vertex colours. Bake-to-vertex-colours has existed since Blender 2.92 ([Victor Karp](https://victorkarp.com/how-to-bake-textures-to-vertex-colors-in-blender/)). The vertex-colour route removes per-asset textures entirely and lets most props share one master material. That fits Valheim's approach: Svensson says composition and lighting matter more than texture or polygon detail, and low-res textures avoid an uncanny valley that would cost "20x the work" ([Screen Rant](https://screenrant.com/valheim-good-graphics-lighting-low-resolution-textures/)).

**UE 5.8 runs Python headless with `UnrealEditor-Cmd Game.uproject -run=pythonscript -script=…`.** This commandlet does not load levels, and the Python plugin is still labelled Experimental ([UE 5.8 Python docs](https://dev.epicgames.com/documentation/en-us/unreal-engine/scripting-the-unreal-editor-using-python)). glTF goes through Interchange with `ImportAssetParameters(is_automated=True)` ([Interchange 5.8](https://dev.epicgames.com/documentation/unreal-engine/importing-assets-using-interchange-in-unreal-engine?lang=en-US)). Running Interchange inside a commandlet is a known friction point ([forum](https://forums.unrealengine.com/t/interchange-with-python-in-an-unreal-commandlet/724404)), and the legacy `AssetImportTask` path is the fallback. After import, `StaticMeshEditorSubsystem` generates LOD1–3 with `set_lods`, adds simple or convex collision, and sets Nanite. Texture2D exposes `filter`, `mip_gen_settings`, `lod_group` and `max_texture_size` ([StaticMeshEditorSubsystem](https://dev.epicgames.com/documentation/en-us/unreal-engine/python-api/class/StaticMeshEditorSubsystem?application_version=5.6); [Texture2D](https://dev.epicgames.com/documentation/en-us/unreal-engine/python-api/class/Texture2D?application_version=5.6)). Leave Nanite off for sub-2k-triangle props. Nearest filtering with mips kept avoids the distant-foliage shimmer Valheim players complain about ([Steam thread](https://steamcommunity.com/app/892970/discussions/0/3104638636526968494/)). Whether `-NullRHI` breaks texture compression on Linux is unverified. Use it for pure import jobs so the flaky GPU stays idle, and fall back to `-ExecutePythonScript` with a render context when a step needs one.

**For scattering, use HISM or PCG fed by data, not Python-wired graphs.** Epic's 5.8 docs recommend HISM for "1000s of instances that don't move". ISM has to cull each instance on the GPU, which is "expensive on lower powered platforms" ([UE 5.8 ISM docs](https://dev.epicgames.com/documentation/en-us/unreal-engine/instanced-static-mesh-component-in-unreal-engine)). Python can create a PCG graph asset and call `generate_local()` on a component. Wiring nodes from Python is poorly documented and a recurring forum question ([forum](https://forums.unrealengine.com/t/create-pcg-graph-with-python/1714891); [PCGComponent](https://docs.unrealengine.com/5.4/en-US/PythonAPI/class/PCGComponent.html)). PCG can read points from a CSV-backed DataTable ([SideFX](https://www.sidefx.com/tutorials/how-to-export-to-pcg-in-unreal/)). So hand-build three to five graphs: palms along the river band, reeds at the water edge, crops in canal zones, and kit pieces on building plots. Drive them from the numpy terrain masks. The simplest bypass writes `scatter.csv` from Python and spawns one HISM component per mesh with `add_instances`.

## A manifest-gated pipeline keeps licences and the repo safe

Every stage should read and write one manifest, and **the UE import script should refuse any file that has no manifest row**. Each row holds: id, source URL, author, SPDX licence, acquisition date, sha256, derived-file glob, whether it was modified, and whether it is AI-made (with tool, model version and prompt). An allowlist check against `CC0-1.0`, `CC-BY-4.0`, `LicenseRef-QAL-1.0`, `LicenseRef-Fab-Standard` and `LicenseRef-Sonniss` should hard-fail on anything NC, ND or SA. NC forbids sale, ND forbids the stylization pass, and SA would spread its terms to derivatives. The **REUSE 3.3 spec** is a standard container for this: licence texts go in `LICENSES/<SPDX-ID>.txt`, with `REUSE.toml` glob annotations or `.license` sidecars ([REUSE spec](https://reuse.software/spec-3.3/)). The same manifest generates the in-game credits DataTable (with CC-BY entries rendered as "Title by Author (URL), CC BY 4.0, modified"), the Steam AI-disclosure list, and the period tags.

The recommended pipeline, in build order:

| Stage | Tooling (all headless on Linux) | Output |
|---|---|---|
| 0. Set-up | Install Blender LTS; `gltfpack`; Pillow/numpy/scipy; display on the iGPU | — |
| 1. Fetch | Python sync scripts: Poly Haven, ambientCG v3 (1K/2K JPG), Kenney scrape, KayKit `git clone`, Met/CMA/Commons/Freesound/Sketchfab queries with licence filters; one-time manual Quaternius, Sonniss and optional Fab | `raw/` keyed by sha256 + manifest rows |
| 2. Generate | Blender bmesh/GN scripts (mudbrick kit, ziggurat terraces, mudhif, reed boat, palm, oxcart); numpy terrain, splat masks and flipbooks; PIL trim sheets and decals | Seeded GLB/PNG + manifest rows |
| 3. AI (optional, 2D) | sd.cpp Vulkan/CPU `--circular`, DeepBump, StableMaterials, Stable Audio Open | Textures, decals, SFX flagged `ai=true` |
| 4. Stylize | Blender: weld, remesh, decimate, flat-shade, vertex-colour bake; Pillow palette lock; gltfpack | `processed/` small GLB and 128–512 px PNG |
| 5. Gate | Licence allowlist, REUSE generation, credits CSV, AI list | Pass or fail |
| 6. Import | `UnrealEditor-Cmd -run=pythonscript`: Interchange import, `set_lods`, collision, texture settings, material instances | `.uasset` via LFS |
| 7. Place | Python: landscape update, `scatter.csv` into DataTable/PCG or HISM `add_instances`; `-ExecutePythonScript` when levels must load | Populated levels |

Keep raw downloads outside git, keyed by sha256, because they can be re-fetched from the manifest. Commit only processed files and `.uasset` through LFS. That keeps the repo small and keeps QAL and Fab originals from spreading beyond the collaborator scope.

## Conclusion

The main finding is that the bottleneck is not finding assets. It is making them look like they belong together. Free sources already cover about 80% of a generic stylized world, but none of that 80% is Ur. The part that makes the game recognisably Ur (the ziggurat silhouette, mudhif arches, palm-lined canals, crescent city plan) has to come from a small library of seeded Blender and numpy generators, and those generators become a lasting project asset that Tommy can extend. It helps that Bronze-Age Mesopotamian architecture is geometrically simple, which suits procedural generation better than most historical settings. Three risks are easy to miss. Licences change quietly, as Quaternius did five weeks before this research, so acquisition dates must be recorded. Heritage scans skew toward later periods, so period tags must be enforced. And the GPU cannot be trusted with long jobs, so everything except sd.cpp should run on the CPU and the import commandlet.
